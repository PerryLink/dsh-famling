# Independent plugin checkout: vendored LOCK, clean-checkout rebuild (MB-004)

> Task: **E1 MB-004** - plugin independent git/CI: vendored spec + LOCK; a
> plugin-only checkout must build/test/verify without the private `famling`
> repository. Companion: [`PUBLIC-REPO-SYNC-2026-11-20.md`](./PUBLIC-REPO-SYNC-2026-11-20.md)
> (public-repo staging).

## 1. Why this exists

`dsh-famling` is a separate npm package from the private `famling` desktop app.
The plugin ships every animation frame inside its own lazy chunks
(`client.anims.{human,cat,dog}.js`), but the development-time generators read
the sibling private checkout (`../desktop-games`) as their art source:

| File | Private dependency before MB-004 |
|---|---|
| `scripts/embed-anims.mjs --check` | failed outright when
`../../desktop-games/public/assets/pet/anim` was absent |
| `scripts/verify-anims.mjs` | silently skipped its byte-level asset cross-check
(`warn: private animation assets not found; skipped ...`) |
| `test/client-static.test.js` (2 tests) | `t.skip('private ... not available')` |
| `scripts/typecheck.mjs` | resolves TypeScript from the sibling checkout when
present, but skips honestly when absent (no runtime dependency) |

Consequences: a plugin-only checkout could not run `npm run check`, had no
reproducible install LOCK, and its `verify` gate did not actually verify the
checked-in frames. MB-004 closes that with two vendored artifacts plus a
clean-checkout gate.

## 2. Deliverables

### 2.1 `package-lock.json` (reproducible install LOCK)

- Zero runtime dependencies by design, so the lockfile is a root-only
  `lockfileVersion: 3` tree (323 bytes, 1 locked package).
- `npm ci --offline --ignore-scripts` succeeds from the lock alone in a empty
  checkout: no network, no private repo, no `node_modules` needed for the
  plugin's `node --test` suite (the plugin is dependency-free).
- `scripts/check-package.mjs` now validates the lock as part of the release
  gate (`npm run check:package` / `verify:package` / `prepack`):
  `lockfileVersion === 3`, name/version/license match `package.json`, every
  declared dependency is represented, no `file:`/`link:`/absolute-path
  resolutions (a lock entry pointing into a private checkout fails the build).
  The check is generic so a future dev dependency must also be locked.

### 2.2 `scripts/spec/anim-spec.json` (vendored semantic spec + SHA LOCK)

Generated by `scripts/embed-anims.mjs` (embed/update mode) and committed to
the plugin repository. It contains **no PNG/base64 art bytes**; it is the
public semantic manifest plus SHA-256 locks:

| Field | Meaning |
|---|---|
| `schema` / `specVersion` | `dsh-famling/anim-spec` / `1` |
| `sourceSha256` | the same aggregate digest printed in `client.js`
(`// source-sha256: ...`), covering the private regions + clip metadata +
source PNG bytes used for the last generation |
| `characters.<kind>.clips` | per-clip fps/loop/holdMs/durationMs/frames
contract (the shared `famling.pet-anim/0.1` data) |
| `characters.<kind>.regions` | the full tap-region/actions document
(head/body/tail zones, random says, species actions) |
| `characters.<kind>.chunkSha256` | SHA-256 of the committed lazy chunk file |
| `characters.<kind>.embeddedFrameSha256[]` | SHA-256 of every embedded
(re-encoded) frame PNG, in clip/frame order |
| `sourceFrames.<kind>.<clip>/<clip>_NN.png` | SHA-256 of every private source
frame file (public manifest of the art; bytes stay private) |
| `specSha256` | self-digest over the canonical (recursively sorted-key) spec
body |

Reader/validator: `scripts/anim-spec.mjs` (`readAnimationSpec`,
`validateEmbeddedAgainstSpec`). A missing spec, unknown schema/version, broken
self-digest, edited chunk, edited frame, or changed clip/region contract is a
hard error - never a skip.

### 2.3 Standalone gate behavior

- `node scripts/embed-anims.mjs --check` with no private assets:
  `[embed-anims] standalone spec mode: ... (no skip)` and validates the
  committed `client.js` + 3 chunks against the spec (source digest, chunk
  hashes, frame hashes, clip/region contract).
- With the private checkout present: it still regenerates from the art source
  and additionally fails if the committed spec is stale (`run npm run
  embed:anims`), so the vendored lock cannot drift from the artifacts.
- `node scripts/verify-anims.mjs` always validates the vendored spec. When the
  private checkout is absent it prints `private assets: absent (vendored spec
  is the verification source)` instead of a skip warning.
- `scripts/gen-content-constants.mjs --check` already had a static fallback
  (`static block check ok`) for a plugin-only checkout; unchanged.
- The 2 former private-asset tests in `test/client-static.test.js` now run
  against the vendored spec when the private checkout is absent.

### 2.4 `scripts/clean-checkout.mjs` (clean-checkout rebuild gate)

Copies the package into a fresh temp directory (no `.git`, no `node_modules`,
no tarballs), points `FAMLING_ANIM_DIR` / `FAMLING_CHARACTERS_DIR` /
`FAMLING_REPO_DIR` at a nonexistent path, then runs and asserts:

1. `npm ci --offline --ignore-scripts --no-audit --no-fund` (LOCK);
2. `node --test test/*.test.js` - **0 failures**, every remaining skip is a
   documented cross-repo `famling` parity skip (see 4 below);
3. `node scripts/embed-anims.mjs --check` - **standalone spec mode**;
4. `node scripts/verify-anims.mjs` - vendored spec OK, private assets absent;
5. `npm run check` - the package's own check script, so any gate wired into it
   later (i18n, generated single-source checks, ...) also runs standalone;
6. `node scripts/check-package.mjs --pack` - metadata/files/lock + real
   `npm pack --dry-run` inventory;
7. `node scripts/check-jsdoc.mjs`;
8. `node scripts/typecheck.mjs` (real `checkJs ok` when a compiler is
   available, honest `skipped: TypeScript is not installed here` otherwise).

Commands:

```
node scripts/clean-checkout.mjs            # temp checkout + all gates (deleted)
node scripts/clean-checkout.mjs --keep     # keep the temp checkout path
node scripts/clean-checkout.mjs --json     # machine-readable evidence
node scripts/clean-checkout.mjs --export DIR           # stage public-repo tree
node scripts/clean-checkout.mjs --export DIR --verify  # staged tree + all gates
```

`test/clean-checkout.test.js` runs this gate inside `npm test` (the child test
suite sets `DSH_FAMLING_STANDALONE_CHILD=1`, so the copy registers only the
static LOCK/spec checks instead of spawning another full checkout - no
recursion). `test/anim-spec.test.js` pins the spec/lock invariants and the
tamper/missing-spec failure modes.

| `npm run typecheck` | `checkJs ok` (TypeScript resolved from the sibling dev checkout) |
| `npm run lint` | `[check-jsdoc] ok` |
| `npm run verify:package` | `pack ok (20 files, ...)`, lockfileVersion 3 |
| `node scripts/clean-checkout.mjs --json` | `ok: true`; full package copy (no `node_modules`/`.git`); temp
checkout **no private repo**; 0 test failures; 10 cross-repo skips (all
`famling` parity); embed `standalone spec mode`; verify `OK`; package `pack ok`;
typecheck honest skip (no compiler in the temp checkout) |
| `node scripts/clean-checkout.mjs --export DIR --json` | `ok: true`; staged
public-repo tree; `check-package` static + standalone spec check pass |

A stale/tampered commit fails loudly. Verified negative cases:

- delete `scripts/spec/anim-spec.json` -> `embed --check` exits 1 with
  `vendored animation spec is missing ... never skip the private-asset gate`;
- edit one base64 character of a committed frame -> exit 1 with
  `chunk ... sha256 ... != vendored spec ...` and `frame ... != vendored spec`;
- change `specSha256` or any spec field -> `integrity check failed` /
  `embedded ... differs from the vendored spec`.

## 4. Known limits / honest remaining state

- **10 cross-repo skips remain in a plugin-only checkout** (the full test
  count grows with other tasks; the 10 are stable). They are the deliberate parity gates that
  compare the plugin's frozen copy against the sibling `famling` checkout
  (`public/content/library.json`, behavior rules, limits/terms anchors, shared
  compliance fixtures). They do not gate the plugin build and are skipped only
  when that sibling repository is absent; the vendored compliance fixtures in
  `test/fixtures/content-compliance/` already run locally. The clean-checkout
  gate asserts every remaining skip is one of these `famling` cross-repo
  checks and that **no private-asset/region skip remains**.
- **TypeScript is deliberately not a dependency** (the package stays
  install-free). In a bare checkout `typecheck` prints its documented honest
  skip; in this workspace it resolves the sibling `desktop-games` compiler and
  reports `checkJs ok`. CI can install TypeScript dev-only and set
  `FAMLING_TSC` if a real checkJs run is required (see
  [`PUBLIC-REPO-SYNC-2026-11-20.md`](./PUBLIC-REPO-SYNC-2026-11-20.md)).
- **No `.git` / no CI first run in this workspace** (MB-001 is external). The
  plugin source directory here is not a git repository; first push, CI and
  branch protection are staged by the public-repo export but were not executed
  by this task (no commit/push per workspace instructions).
- The generated chunk/header comments still name the private producer layout
  (`../../desktop-games/...`) as provenance. That is a comment, not a build
  input: the clean-checkout gate proves the package rebuilds/verifies without
  that path existing.

## 5. Acceptance mapping

| Requirement | Where |
|---|---|
| vendored spec + LOCK | `scripts/spec/anim-spec.json`, `package-lock.json` |
| embed/verify read spec/LOCK, no default private repo | `scripts/anim-spec.mjs`, `scripts/embed-anims.mjs`, `scripts/verify-anims.mjs` |
| missing spec fails, never skips | `readAnimationSpec` + `--check` exit 1 |
| no private repo -> test/check/verify green | `scripts/clean-checkout.mjs`, `test/clean-checkout.test.js` |
| stale artifacts after a frame edit -> red | spec chunk/frame SHA checks |
| package still builds/packs | `verify:package` in the clean checkout |

## 6. Regenerating the vendored spec

Run in a checkout that has the private art source (the workspace sibling):

```
node scripts/embed-anims.mjs          # rewrites chunks/client.js if changed AND
                                      # refreshes scripts/spec/anim-spec.json
node scripts/embed-anims.mjs --check  # must be green before commit
npm test                              # includes test/anim-spec.test.js
```

If only `scripts/spec/anim-spec.json` changed, the commit is the spec refresh
plus whatever regenerated chunks/client.js bytes changed with it - never hand-
edit the spec or the generated blocks.
